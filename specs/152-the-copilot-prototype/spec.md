# Spec 152 -- The copilot prototype: a local page and server for the founder's hand test

Design of record: the UX page of 2026-11-11, "The founder copilot, designed around what it gets wrong" (`~/Documents/projects/keel-marketing/handoff-2026-11-09/copilot/copilot-ux-from-the-bench.html`, artifact LDexgdh49E9oAzpQZ27nGz v1), built from round 1 of the call bench (spec 151; runs `20261111T002823Z-copilot-bench-r1-text` and `20261111T025859Z-copilot-bench-r1-audio`). The founder's order of 2026-11-10 22:15 ET: "create a UX for a copilot based on your learnings from both the test and then creating a small prototype out of it so that we can test it manually." The prototype is Stack 1 of the bench, exactly as it ran, behind a page the founder opens on his laptop during a real Google Meet. It is an eval-repo tool, not product code: no sign-in, no Sent row, no project, nothing in keel-cloud or keel-web.

The five rules it must embody (each from a measured number on the page): (1) the founder never waits for the box, the card has a **Now** row and a **Filed** row and captures land late underneath; (2) the founder speaks freely, every founder turn is mapped and an off-script question is filed as a note under the question just asked, no pause state; (3) the question's **frame** words are shown as pills and the filed answer repeats the frame it was filed under, a `meaning_changed` verdict marks the pills not heard; (4) unsure means the keys: unsure shows "I did not catch that" with the options numbered, likely files in amber with the others numbered, sure files in green with undo; (5) a stuck turn is the founder's to file: after 5 s the Filed row says "still working, carry on", after 20 s it shows the options numbered and the next turn is never blocked.

## Rules

- **FR-1 The server.** `evals/copilot/prototype/server.py`: a `ThreadingHTTPServer` on `127.0.0.1` (default port 8765, `PORT=`) with three routes. `GET /` serves the page and its script and stylesheet from `evals/copilot/prototype/` (plain files, no templating, no CDN, no framework). `POST /turn` takes one turn: a JSON header part (`who`: founder|them, `seq`, `started_at`, `ended_at`, wall clocks from the page) and a 16-bit mono WAV body (multipart or a `?who=&seq=` query with the WAV as the body, the builder's choice, documented in the module docstring); it transcribes with `HttpClients.transcribe(wav, keywords=base.keywords(q, current), prompt=turn_by_turn.TRANSCRIBE_PROMPT)`, classifies with `base.haiku_body(instruction('copilot-match.md'), turn_by_turn.match_prompt(q, current, state, who, heard))`, reads the reply through `base.event_from`, advances `current`/`state` with `base.advance` exactly as `TurnByTurn.run` does, and returns the event as JSON (`q, verdict, option, tier, state, heard, reply, parts{transcribe, classify}, seq, who`). `POST /key` takes `{key, seq_of_turn|null, at}` and applies the founder's filing to the server's record: `1`-`6` file that option for the question in the Filed row, `0` the escape, `X` keeps the reply as a note (`verdict: "nothing"`, option null), `F` clears a frame flag, `Z` undoes the last filing, `→`/`Space` moves `current` to the next unanswered item, `←` to the previous, `P` toggles listening; the server replies with the state the card should show. Turns are handled in arrival order per side, and a turn whose vendor call takes longer than 20 s still completes and is recorded when it does. Keys come from `clients.keys_from(os.environ)` (`KEEL_OPENAI_API_KEY`, `KEEL_ANTHROPIC_API_KEY`); the server refuses to start without both and never writes a key anywhere. `make copilot-prototype [PORT=8765] [QUESTIONNAIRE=evals/copilot/fixtures/questionnaire-08-fresco.json]` starts it and prints the URL; it opens no browser.
- **FR-2 The page.** `evals/copilot/prototype/copilot.html`, `copilot.js`, `copilot.css`: vanilla, Chrome on the desktop. Two sources: **Microphone** (`getUserMedia`) is the founder; **Share** (`getDisplayMedia({audio: true, video: true})`, the Chrome-tab pane, the video track dropped) is the respondent. **Rehearsal** mode: one microphone, and the `T` key switches which side the next turn belongs to, shown on the card. Turn cutting per source with an `AnalyserNode`: a turn opens when the level is above a threshold for 150 ms and closes after 0.7 s below it (`base.TURN_END_HOLD`), turns under 0.4 s are dropped; the page encodes the turn's samples as 16-bit mono WAV (24 kHz, or the context's rate, stated in the header) and posts it. While a turn is in flight the next turns queue in order; the card never waits for a reply before the next turn can be cut. The page keeps a wall clock per turn (speech end -> reply shown) and shows the split the server returns.
- **FR-3 The card.** The UX page's card, state for state: header (dot: listening / working / hand-over / done, question n of N, progress), **Now** (the current question's text with its frame pills; the `Asked differently?` flag with `F` keep / `X` note when the verdict was `meaning_changed`, the pills whose words are absent from the founder's heard turn marked), **Heard** (one line, who and the words, "heard nothing" on an empty transcript), **Filed** (the last answer: sure green with the frame spelled out and `Z` undo / `X` note; likely amber with the pick and the other options numbered; unsure amber "I did not catch that" with every option numbered, `0` the escape, `X` note; an off-script founder turn "Your own question, kept as a note under Qn"; "still working, carry on" after 5 s and the options numbered after 20 s; "Done" after the last item), and the key legend footer. `Float` opens the card in `documentPictureInPicture.requestWindow({width: 380, height: 560})` (stylesheets copied, the card node moved, returned on `pagehide`); `Esc` floats or returns it. The keys of the UX page's table, all of them, on `keydown` in whichever window holds the card; nothing is spoken to the box. The card moves by itself when a founder turn maps to another question (`base.advance`), and by key. Five minutes with no turn on either source shows "Paused · five minutes of silence" until a turn or `P`. **Frame pills** come from a data file `evals/copilot/prototype/frames.json` keyed by item id (window, unit, anchor phrases for the Fresco fixture's six items; a missing id means no pills), not from code.
- **FR-4 The log.** A run folder `runs/<ts>-copilot-prototype/` with `turns/<seq>-<who>.wav`, `events.jsonl` (the bench's event shape plus `heard`, `reply`, `parts`, `seq`, `who`, `wall{ended_at, shown_at}`), `keys.jsonl`, and `session.json` (questionnaire path, mode, started, ended, items filed by the box / by key / as notes). The shape matches a bench run's so a hand call can be scored later; a `register` is not written.
- **FR-5 Tests.** `tests/test_copilot_prototype.py`: the server's routes against `FakeClients` (a founder turn maps and advances, a respondent turn files, an echoed verdict on a respondent turn still files, an empty transcript returns `heard: ""`, each key does what FR-1 says, `Z` undoes, a slow turn still lands); WAV decode of a page-made header; the log's files and shapes; refusal without both keys; `frames.json` keyed by the fixture's ids; the page references only files the server serves. The page's JavaScript is exercised by reading, not by a browser: no new test dependency.
- **FR-6 AGENTS.md.** One paragraph under the bench's: what the prototype is, the command, where its log goes, that it is not product code.
- **FR-7 Nothing else.** No change to `evals/copilot/stacks/`, `score.py`, `bench.py`, `catalogue.py` or `instructions/` (the bench is running from master while this is built); no new dependency beyond the venv's; no key in any file; no product repo touched; no trade or company word in code (the questionnaire and `frames.json` are data).
